Yanushi UX refresh

UI vocabulary

The complete set of shared atoms. A screen is composed of these plus Tailwind layout utilities. If a screen seems to need a new atom, add it here and to yanushi-ui.css first.

Buttons

Text link
  • At most one yn-btn-primary per screen.
  • yn-btn-danger lives inside the confirm dialog or an overflow menu, not in page headers.
  • A disabled primary action must be accompanied by visible text explaining the blocker (see Alerts).
  • No emoji in button labels. Icons are optional 16px inline SVG.

Form fields

Dollars and cents, e.g. 2,400.00

Payment method can’t be blank

  • Every control gets a <label for>. Errors use yn-field-invalid + aria-invalid + aria-describedby pointing at the yn-error-text.
  • Money inputs add tabular-nums and inputmode="decimal".

Ordinary metadata is plain text separated by middots: Single family · 2,200 sqft · 1 unit
  • Status = dot + word. The word carries the meaning; the dot only reinforces it (never color alone).
  • Colored pills/badges for ordinary metadata (asset type, dimensions, categories) are retired.

  • Money columns: text-right tabular-nums on both th and td. Amounts always show cents.
  • Credits/receipts use a real minus sign (−). Balance columns append the word due or credit; balances never rely on sign color.
  • Voided/corrected rows stay in place: strikethrough + neutral status, linked to the correction.
  • No zebra striping. Hover highlight only.

  • The dialog title is the verb phrase of its one primary action; the confirm button repeats it.
  • The <dialog> element must carry aria-labelledby pointing at the header (missing in the current layout — fix in M1).
  • Validation failure re-renders the form inside the frame with a 422; the dialog stays open.
